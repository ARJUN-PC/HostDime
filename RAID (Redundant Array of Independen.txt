4.Why /etc/resolv.conf and /etc/hosts files are used?

/etc/resolv.conf
>> This file is used for DNS (Domain Name System) resolution. It tells the system which DNS servers to use when resolving domain names to IP addresses.
Content: nameserver 8.8.8.8  # Google's DNS
nameserver 1.1.1.1  # Cloudflare's DNS
search example.com  # Default search domain
options timeout:2   # Timeout for DNS queries

Use Case
When you type ping google.com, your system checks /etc/resolv.conf to find the DNS server to query for the IP address of google.com.

/etc/hosts
>> This file provides local static hostname-to-IP address mappings. It is used before DNS queries and helps resolve hostnames without querying external DNS servers.

Use Case
When you type ping server1, your system first checks /etc/hosts before querying a DNS server. If server1 is mapped to an IP in /etc/hosts, it will use that mapping directly.

10.How do you troubleshoot database performance issues?

Check Server Resources – Monitor CPU, RAM, disk I/O, and network usage to ensure the server isn’t overloaded.

Analyze Slow Queries – Use MySQL’s slow_query_log or EXPLAIN to find inefficient queries and optimize them (e.g., adding indexes).

Check Indexing – Ensure proper indexes exist to speed up queries. Over-indexing can also degrade performance.

Monitor Locks & Contention – Use SHOW PROCESSLIST or INNODB STATUS to detect deadlocks and excessive row locking.

Optimize Configuration – Tools like MySQLTuner (which you are familiar with) help adjust settings in my.cnf for better performance.

Analyze Connections – Ensure connection pooling is used efficiently and avoid excessive open connections.

Check Query Execution Plans – Use EXPLAIN ANALYZE to inspect how queries execute and identify inefficiencies.

Monitor Database Growth – Large tables and fragmentation can slow down performance; consider archiving old data.

Optimize Caching – Implement query caching, object caching (e.g., Redis), or database-level caching where applicable.

Review Application Code – Poorly written application logic can generate unnecessary database load.
